# Rubric: is this reproduction package ready to post?

Grade only from the evidence named in each row. Judge the thing itself
against the issue, never the write-up's headings or length. An honest,
evidenced cannot-reproduce can still be ready to post.

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| env_recorded | The repro report's environment record, read against the issue's stated target (version, OS, or platform in the issue body or repo-facts "bug reports" line). | Pass if the report names (1) an OS or platform and (2) the version or commit of the software under test. If those values differ from the issue's stated target, pass only when the report names the difference. Fail if either (1) or (2) is missing. | required |
| steps_followable | The repro report's steps, commands, and any files or flags they use. | Pass if a stranger who has only this package could start from a stated starting state and reach the trigger using the commands or actions written there. A short description of a small input is enough when the issue already names that input's shape (for example "a valid dependencies list plus a category: section"). Fail if a step depends on a private repo, an unshared config, or a flag/file a stranger cannot obtain, or if the trigger the issue names is skipped. | required |
| artifact_matches_issue | The repro report's output excerpts, logs, exit codes, or screenshots, read against the issue body's described behavior (the error, panic, missing header, freeze, or other symptom the issue actually reports). | Pass if the shown artifact is the same kind of failure the issue describes, produced by the issue's trigger (or an equivalent the report names). Fail if the artifact is a different failure (wrong flag, swapped operator, compile error instead of the reported runtime error, graceful validation instead of a crash, garbled output presented as a crash), or if the run used a different target version without saying so. An evidenced cannot-reproduce still passes this check when the artifacts show the attempt at the issue's trigger and do not claim the issue's symptom appeared. | required |
| honest_outcome | The claim comment and the repro report's expected/actual (or equivalent outcome sentences), read against the artifacts in the same report. | Pass if every claim of "reproduced", "confirmed", or "cannot reproduce" is backed by the artifacts: a reproduce claim requires an artifact of the issue's symptom; a cannot-reproduce claim requires artifacts of the attempt plus what differed. Fail if the words claim more than the artifacts show (no artifact, setup-only output treated as the bug, a diagnosis with no transcript, or a wrong-target artifact narrated as the reported bug). | required |
| claim_names_issue | The candidate claim comment, read against the issue title/body. | Pass if the claim names this issue's concrete symptom or trigger (a command, file, error, or behavior from the issue) and states a next step that is an investigation or a repro report, not a promised fix or a date. Fail if the claim is a +1, an assign-me with no issue specifics, or a guarantee to fix it by a deadline. | required |
| ai_disclosure | Repo facts "contribution policy" line, plus the claim comment and the repro report. | Fail only when that policy requires disclosing AI use on issues or comments (wording such as "must be disclosed" or "AI-assisted issues and comments must" disclose) AND neither comment discloses AI assistance. Pass when the policy is silent, when it only sets conditions for pull requests, or when at least one of the two comments discloses the tool or that AI assistance was used. | required |
| control_or_delta | The repro report: a control run, or a named environment difference that explains a cannot-reproduce. | Pass if the report includes a contrasting control run, or (for cannot-reproduce) names a concrete difference from the reporter's setup. Otherwise fail. Never changes the verdict. | preferred |

## Verdict rule

Accept only if every required check (`env_recorded`, `steps_followable`, `artifact_matches_issue`, `honest_outcome`, `claim_names_issue`, `ai_disclosure`) is `pass`. A `fail` or `unclear` on any required check is a reject. Preferred checks never change the verdict. In live mode on a claim-only draft, skip every check whose evidence needs the repro report (`env_recorded`, `steps_followable`, `artifact_matches_issue`, `honest_outcome`, `control_or_delta`): grade those `unclear` with evidence `not yet applicable: claim-only draft`, and do not let them decide the verdict. The claim-only verdict is then accept only if `claim_names_issue` and `ai_disclosure` both pass.
